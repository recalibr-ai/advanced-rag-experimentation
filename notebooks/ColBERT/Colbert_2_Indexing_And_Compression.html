🔑 Key Point: Each Chunk Gets Its Own Codebook!

2 chunks = 2 separate K-means = 2 different codebooks
(Real ColBERT uses 4 chunks from 128D → 4 codebooks)

Why separate? Each embedding position has different statistical patterns!
Position 0-1 might encode "semantic strength", position 2-3 might encode "syntax"
Specialized codebooks = much better compression for each position's unique patterns

🎯 Why K-Means Works So Well

256 clusters per chunk: Captures fine-grained patterns in embedding space
Trained on real data: Clusters reflect actual token distribution, not random
Minimizes distances: Residuals are tiny because centroids are optimally placed
Per-chunk specialization: Each position learns its own common patterns
K-means training on millions of real token chunks creates optimal cluster centers that minimize residuals

📐 Residual Calculation & Quantization

Step 3: Calculate Residuals

Chunk 1: [0.847, 0.293] - [0.8, 0.3] = [0.047, -0.007]
Chunk 2: [0.108, 0.926] - [0.1, 0.9] = [0.008, 0.026]
Key insight: Residuals are TINY because centroids are close!
↓

2-Bit Quantization Levels

Level 0: -0.05
Level 1: -0.01
Level 2: 0.01
Level 3: 0.05
→

Quantized Residuals

[0.047, -0.007] → [0.05, -0.01]
[0.008, 0.026] → [0.01, 0.01]
2 bits per dimension = 8 bits total

Step 4: Final Storage

Codes: [2, 1] → 2 bytes (1 byte per code)
Quantized residuals → 1 byte (2 bits × 4 values)
Total: 3 bytes instead of 512 bytes!
Aggressive quantization of tiny residuals is the secret to massive compression

Document lengths, offsets,

All cluster centroids

🔍 Inverted Index Concept

Purpose: Instantly find which documents contain tokens from specific clusters
Structure: Each cluster points to list of documents containing tokens from that cluster
Benefit: No need to scan all documents during search
Smart file organization enables both efficient storage and lightning-fast retrieval

🔍 How Lookups Actually Work (PLAID Stage 1)

PLAID has 3 stages:
Stage 1: Inverted Index Lookup (explained below)
Stage 2: Approximate scoring with cluster centroids
Stage 3: Exact ColBERT MaxSim scoring
We're focusing on Stage 1 - the inverted index lookup that does the heavy filtering
